# Как собрать полотно для Полотна

Гайд для агентов (и людей), которые генерируют файлы `.polotno`. Всё ниже проверено на живом приложении: цифры взяты из его CSS и кода, а не придуманы.

**Перед сдачей прогони проверку:**

```bash
node scripts/check-canvas.mjs твоё-полотно.polotno
```

Скрипт без зависимостей (Node 18+). Он находит наложения карточек, нечитаемые издалека заголовки, связи сквозь карточки и чужие группы, спрятанные подписи, повторяющиеся подписи, перекосы формата. Ошибки обязательно исправить, предупреждения разобрать. Образцы, которые проходят проверку начисто: [`docs/demo/example-minimal.polotno`](demo/example-minimal.polotno) (6 карточек, читается глазами) и [`docs/demo/polotno-tour.polotno`](demo/polotno-tour.polotno) (все типы карточек и режимы).

---

## 1. Что такое Полотно и чем оно не является

Полотно — бесконечный холст, где **общая картина и детали лежат на одной поверхности**. Издалека проект виден как структура, вблизи — как тексты и медиа. Связи в первую очередь **причинные**: А ведёт к Б, Б требует В.

Из этого следуют три правила, которые важнее всех остальных:

1. **Карточка — одна мысль.** Не раздел документа и не страница. Если текст не помещается в карточку без «Развернуть», это две-три карточки, связанные между собой.
2. **Заголовок — суть в первых двух словах.** Издалека от карточки остаётся только начало заголовка (см. §4). Метки вроде «КАНОН ·», «ПРЕДЛОЖЕНИЕ ·», «Сцена 2.1 ·» в начале заголовка превращают холст в стену одинаковых плашек.
3. **Связь — это причина, а не «см. также».** Ставь связанные карточки рядом. Пучок длинных линий через весь холст означает, что раскладка не отражает смысл.

Полотно — не таблица, не канбан и не документ, нарезанный на прямоугольники. Сетка «13 столбцов × 4 ряда, в каждой ячейке по 2000 символов» формально откроется, но работать не будет: издалека всё одинаковое, вблизи всё обрезано.

## 2. Формат файла

`.polotno` бывает двух видов, приложение читает оба:

- **JSON** — для агентов это основной вариант. Вложения (картинки, аудио, PDF) кладутся прямо в карточку как `data:` URL или ссылкой `https://…`.
- **zip** с `workspace.json` и папкой `attachments/` — так сохраняет само приложение. В карточках при этом стоят ссылки `att:<имя файла>`. Ссылки `att:` работают **только** внутри zip.

### Скелет

```json
{
  "version": "kobyla-polotno-v041",
  "currentProject": "my-canvas",
  "projects": [
    {
      "id": "my-canvas",
      "name": "Название полотна",
      "groups": [ { "id": "g-why", "title": "Зачем" } ],
      "cards": [
        { "id": "goal", "type": "text", "x": 0, "y": 0, "w": 380, "group": "g-why", "created": 1793520000000,
          "title": "Суть в двух словах", "content": "Одна мысль, до ~300 символов. #тег" },
        { "id": "next", "type": "text", "x": 540, "y": 0, "w": 380, "group": "g-why", "created": 1793520600000,
          "title": "Что из неё следует", "content": "Следствие стоит рядом с причиной. #тег" }
      ],
      "edges": [ { "id": "e1", "from": "goal", "to": "next", "label": "почему ведёт" } ],
      "view": { "x": 120, "y": 140, "scale": 0.8 }
    }
  ]
}
```

### Полотно (элемент `projects`)

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | `[A-Za-z0-9_-]`, до 64 символов. Это имя файла на диске |
| `name` | да | Название в меню полотен и в заголовке окна |
| `cards`, `edges`, `groups` | да (можно пустые) | См. ниже |
| `view` | нет | `{ x, y, scale }` — с какого вида открыть. Без него приложение само покажет всё полотно |

### Карточка

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | Уникальная строка в пределах полотна |
| `type` | да | Один из девяти типов (таблица ниже) |
| `x`, `y` | да | Левый верхний угол в единицах холста. Ось Y направлена вниз |
| `w` | да | Ширина, 200…1200. Рабочий диапазон 300…420 |
| `title` | да | Заголовок. См. §4: от него зависит, читается ли полотно издалека |
| `content` | да | Зависит от типа |
| `group` | нет | `id` группы. Карточка состоит максимум в одной группе |
| `created` | нет | Время создания, мс с 1970. По нему строится **таймлайн**; без него все карточки попадут в «Без даты» |
| `filename`, `size` | нет | Имя и размер файла для `image`, `video`, `audio`, `pdf`, `file` |
| `customHeight` | нет | Фиксированная высота (для `text`/`markdown`: тогда внутри прокрутка вместо «Развернуть») |
| `expanded` | нет | `true` — длинный текст сразу развёрнут (до 460px высоты тела) |

Высоту задавать не нужно: приложение считает её само по содержимому. Но **раскладывать карточки приходится с учётом высоты** (см. §5).

### Типы карточек

| `type` | `content` | Заметки |
|---|---|---|
| `text` | Обычный текст, переносы строк сохраняются | Основной тип. До ~300 символов при `w: 380` |
| `markdown` | Markdown: `#`–`###`, списки, `**жирный**`, `*курсив*`, `` `код` ``, ссылки, цитаты, блоки кода | Для структурированного текста. Заголовки внутри занимают место, считай строки |
| `link` | `https://…` | Можно сразу положить `preview: { title, description, site, image }`; `image` — URL или `data:`. Без превью приложение покажет адрес и кнопку «Загрузить превью» |
| `image` | `data:image/…;base64,…`, `https://…` или `att:` | Высота = ширина × пропорции картинки |
| `video` | `data:video/…`, `https://…` или `att:` | |
| `audio` | `data:audio/…`, `https://…` или `att:` | Плеер высотой ~54px |
| `youtube` | **id ролика** (`dQw4w9WgXcQ`), не ссылка | Превью и плеер YouTube |
| `pdf` | `att:` (в zip) | `thumb` — картинка первой страницы, `pages` — число страниц. Без `thumb` будет заглушка: превью приложение рисует само, когда PDF кидают на холст |
| `file` | `att:` или `data:` | Любой файл: имя, размер, кнопки «Открыть» и «Сохранить» |

### Связь

| Поле | Что это |
|---|---|
| `id` | Уникальная строка |
| `from`, `to` | `id` карточек. Стрелка рисуется у `to`. Направление: **причина → следствие**, «раньше → позже», «общее → частное» |
| `label` | Подпись на линии. Может быть пустой (см. §6) |

### Группа

`{ "id": "g-risk", "title": "Риски" }`. Рамка **не хранит геометрию**: это габарит карточек группы плюс 28px отступа, а над рамкой ярлычок с названием. Отсюда следствие: чужая карточка внутри этого габарита окажется «в рамке», хотя группе не принадлежит. Проверка ловит это как ошибку.

## 3. Как думать о содержании

- **Сначала структура, потом текст.** Выпиши 5–9 крупных узлов (это будущие группы или ряды), затем причинные цепочки между ними, и только потом детали.
- **Длинный материал раскладывай вглубь, а не вширь.** Ключевая мысль в карточке, детали — в 1–3 карточках прямо под ней (`markdown`), со связью «подробнее» вниз. Не выкладывай отдельным рядом «все подробности всех сцен» на другом конце холста.
- **Статусы, категории и пометки — в группы и `#теги`, а не в заголовок.** `#канон`, `#идея`, `#вопрос`, `#риск`. По тегам работают поиск (`Ctrl+F`) и подсказки связей (`L`).
- **Типы карточек — по смыслу.** Источник — `link`, структурированный текст — `markdown`, схема или фото — `image`. Полотно из одних `text` скучно и хуже читается: у типов разные цвета, их видно издалека.
- **Навигационная карточка «как читать полотно» не нужна,** если структура понятна из групп и связей. Если нужна, она короткая и стоит первой (корнем маршрута).
- **Даты `created` задавай осмысленно:** порядок появления идей, хронология сюжета, этапы. Таймлайн тогда рассказывает историю, а не сваливает всё в «Без даты».

## 4. Читаемость на всех масштабах

У Полотна четыре уровня детализации. От масштаба зависит, что останется от карточки:

| Масштаб | Что видно | Что это значит для автора |
|---|---|---|
| ≥ 50% | Карточка целиком: тип, заголовок, текст до ~150px высоты, медиа | Текст длиннее ~300 символов обрежется под «Развернуть» |
| 32–50% | Только заголовок шрифтом 38px, по центру, **до 3 строк**, с переносом по словам | В строку влезает около `(w − 32) / 21` букв: при `w: 380` это ~16, то есть заголовок до ~48 символов. **Самое длинное слово должно влезать в строку**, иначе браузер разорвёт его посередине («Семантически / й») |
| 18–32% | Заголовок 70px **в одну строку** шириной ~440px | Видно примерно **первые 11 букв**. Они должны отличать карточку от соседей |
| < 18% | Цветные плашки без текста | Различаются только цветом типа и группами |

Практические правила:

- Заголовок до **~40 символов**, суть — первым словом: «Монтаж съест вечер», а не «Риск №2 · Монтаж займёт много времени».
- Самое длинное слово заголовка — не длиннее `(w − 32) / 21` букв. «Презентация» (11 букв) требует `w ≥ 270`, «Семантический» (13) — `w ≥ 310`.
- Ширина карточек **340–420**. Уже 300 крупные заголовки издалека начинают рваться.
- Название группы — **до 28 символов**, иначе ярлычок обрежется. Ярлычки держат экранный размер на любом масштабе, поэтому издалека группы читаются лучше всего. Опирайся на них.

## 5. Раскладка

### Высота карточки

Её считает приложение, но раскладывать нужно заранее. Оценка (так же считает `check-canvas.mjs`, ошибка ~2px):

```
высота ≈ 54                                   отступы, шапка с типом, рамка
       + 16 + 20.8 × строк_заголовка          заголовок 16px; строчная ~8.7px, ЗАГЛАВНАЯ ~11.3px
       + тело
тело:  text           min(150, 21.7 × строк) + 32, если текст длиннее 150px (кнопка «Развернуть»)
                      строка вмещает ~(w − 28) / 8.1 знака
       markdown       то же ограничение 150px, но высота текста считается по блокам: строка 22.4px,
                      у пункта списка +3px и отступ 22px слева, у абзаца и списка поля 6px,
                      заголовки ## 18px × 1.3 с полями 12/6. Список из 5 пунктов — уже ~150px
       expanded: true вместо 150 до 460px, кнопка «Свернуть» — для сводок, которые важно видеть целиком
       image          (w − 28) × высота/ширина картинки
       video, youtube (w − 28) × 0.5625
       audio          54
       link           с превью: (w − 28) / 1.91 + 84; без превью: 76
       pdf            (w − 28) × пропорции первой страницы + 36
       file           76
```

Типичные значения: короткий `text` при `w: 380` — 135–180px, обрезанный длинный — около 250–295, картинка 16:9 — около 290, ссылка с картинкой-превью — около 375.

### Сетка и зазоры

Раскладывай по **столбцам с общим шагом** и **рядам с общей линией верха**: глаз читает такую сетку сразу, а связи получаются прямыми.

| Что | Минимум | Почему |
|---|---|---|
| Между карточками | 24px | Иначе тени и рамки выделения слипаются |
| Между соседями, **связанными подписанной связью** | ширина подписи + 26px (≈ 7px на знак) | Подпись рисуется в середине линии **под карточками** и прячется, если зазор уже. Для подписей до 18 знаков бери зазор 140–160 |
| Между рамками разных групп по горизонтали | 48px, то есть 104px между их карточками | Рамка = карточки + 28px с каждой стороны |
| От низа ряда до верха следующего, если там другая группа | 28 + 46 + 28 + 40 ≈ **140px** | Отступ рамки, ярлычок, отступ рамки и воздух |
| Внутри одной группы между рядами | 60–80px | |

Рабочая сетка для карточек шириной до 400px: столбцы `x = 0, 540, 1080, 1620`. Ряды ставь по высоте самой высокой карточки ряда плюс зазор из таблицы.

### Узоры, которые работают

- **Змейка** для маршрута и истории: ряд слева направо, следующий справа налево и так далее. Каждый шаг стоит рядом с предыдущим, переходы между рядами вертикальные, линии короткие. Так устроено демо.
- **Карточка и детали**: ключевая карточка, под ней в том же столбце 1–3 карточки с подробностями и вертикальной связью. Никаких «подробностей на другом конце холста».
- **Развилка**: причина сверху по центру, следствия рядом снизу. Не больше 4–5 веток с одной карточки: дальше это уже группа.
- **Кластеры**: каждая тема — группа, группы стоят сеткой 2×N, между группами 1–2 связи-моста.

### Чего избегать

- **Связь сквозь чужую карточку или через чужую группу.** Переставь карточки так, чтобы цепочка шла по соседям.
- **Вертикальная связь в левый столбец группы.** Она проходит через ярлычок группы, который сидит над рамкой слева. Заходи в группу через правую часть или делай название группы коротким.
- **Звезда длинных связей.** Если одна карточка связана с десятком далёких, это раскладка, а не смысл: подтяни их ближе или раздели узел.
- **Ряд из 13+ карточек.** Холст шириной 7000px издалека превращается в полоску. Лучше 4–5 столбцов и больше рядов, или группы сеткой.

## 6. Связи и подписи

- **Направление** — причина → следствие (или раньше → позже). На нём строится **презентация**: она начинается с корня (карточки без входящих связей) или с выделенной карточки и идёт обходом в глубину: сначала по исходящим связям слева направо, потом по входящим, несвязанные куски следом.
- **Подпись — короткий глагол, объясняющий переход**: «проверяем спрос», «нужен звук», «оживи», до ~30 знаков. Подпись видна на среднем и ближнем зуме, издалека скрывается.
- **Не повторяй одну подпись на десятке связей.** «Затем», «подробности / обоснование» ×20 — это шум, а не смысл. Если переход очевиден, оставь `label: ""`.
- **Не связывай всё со всем.** Одна-две связи на карточку в среднем — нормально. Карточка вообще без связей допустима, если она отдельная мысль. Таких должно быть мало.

---

## 7. Проверка перед сдачей

1. `node scripts/check-canvas.mjs файл.polotno` — **ошибок 0**, предупреждения разобраны.
2. Если есть возможность, открой файл в Полотне (`Ctrl+O`) и посмотри глазами:
   - весь холст (`1`): структура видна, группы читаются;
   - 30–40%: заголовки различимы, ничего не рвётся посередине слова;
   - 100% (`0`): тексты не обрезаны там, где это важно, подписи связей видны;
   - граф (`Shift+4`): нет лишних узлов-звёзд и потерянных островков;
   - презентация (`P`): маршрут идёт в осмысленном порядке.
3. В отчёте пользователю перечисли, что осталось на предупреждениях и почему.

## 8. Частые ошибки и как их чинить

| Симптом | Причина | Что сделать |
|---|---|---|
| Издалека все карточки одинаковые | Метка статуса в начале заголовка | Метку — в `#тег` и группу, в начало заголовка — суть |
| Много «Развернуть» | Карточки по 1000–5000 знаков | Разбей на карточки-мысли; структурное — в `markdown`; детали — под родителем |
| Слово рвётся посередине издалека | Узкая карточка и длинное слово | `w ≥ 32 + 21 × длина_слова` |
| Подпись связи не видна | Зазор между карточками уже подписи | Раздвинь до ширины подписи + 26px или сократи подпись |
| Пучки линий через холст | Связанные карточки далеко друг от друга | Ставь следствие рядом с причиной; детали — под родителем |
| Чужая карточка внутри рамки группы | Рамка — это габарит карточек группы | Вынеси карточку за габарит или добавь её в группу |
| Таймлайн пустой | Нет `created` | Проставь время по смыслу |
| Подсказки связей (`L`) ничего не находят | Нет тегов, тексты короткие и разные | Общие `#теги` и ключевые слова |
| Ссылка `att:` не открывается | `att:` в JSON-файле | В JSON — `data:` URL или `https://`; `att:` только в zip |
| YouTube не играет | В `content` полная ссылка | Только id ролика |
